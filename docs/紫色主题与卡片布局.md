# 紫色主题 & 首页大图卡片

## 一、紫色配色

分两层实现：

### 第 1 层：主题内置的 `theme_color`（`_config.butterfly.yml`）

主题自带配色开关，改这里能让**绝大部分**元素变色：

```yaml
theme_color:
  enable: true
  main: "#A06BFF"          # 主色（取自头像/封面的渐变紫）
  paginator: "#C4A2FF"
  button_hover: "#8A4DFF"
  text_selection: "#B98CFF"
  link_color: "#A98BFF"
  code_foreground: "#E3B7FF"
  # ... 见配置文件
```

⚠️ 这些值由 **Stylus 在编译期**注入 CSS，所以改完**必须 `hexo clean && hexo generate`**，
只重启 server 没用。

### 第 2 层：`source/css/yuu-purple.css`（自定义覆盖）

主题还留了一批 `theme_color` 管不到的地方，通过覆盖 **CSS 变量**解决：

| 变量 | 主题原值 | 现在 | 影响 |
| --- | --- | --- | --- |
| `--global-bg` | `#0d0d0d` 纯灰黑 | `#100B1C` 紫黑 | 页面背景 |
| `--card-bg` | `#121212` | `#1A1428` | 卡片背景 |
| `--sidebar-bg` | `#121212` | `#1A1428` | 侧栏 |
| `--hl-bg` | `#171717` | `#191228` | 代码块 |
| `--scrollbar-color` | `#525252` | `#6B4FA8` | 滚动条 |

还加了：
- 顶部一层紫色径向辉光（`body` 的 `background-image`）
- 卡片悬浮时紫色描边 + 上浮 4px
- 封面图悬浮时放大 1.06 倍

**为什么用覆盖变量而不是直接改主题源码？** 主题升级时不会冲突，删掉这个文件就恢复原样。

**覆盖能生效的前提**：本文件必须在主题样式**之后**加载。
主题的 `inject.head` 位于 `head.pug` 末尾，正好满足。

### 保留的语义色

提示框的警告(橙)/成功(绿)/危险(红)/信息(蓝) **故意没改**——它们表达含义，
改成紫色会让「警告」和「成功」看起来一样。

## 二、首页大图卡片

`_config.butterfly.yml`：

```yaml
index_layout: 4   # 封面在上，信息在下
```

主题提供的 7 种布局：

| 值 | 效果 |
| --- | --- |
| 1 | 封面在左，信息在右 |
| 2 | 封面在右，信息在左 |
| 3 | 左右交替 |
| **4** | **封面在上，信息在下（大图卡片）** |
| 5 | 信息压在封面上 |
| 6 | 瀑布流 - 封面在上 |
| 7 | 瀑布流 - 信息在封面 |

配套调整在 `yuu-purple.css` 末尾：封面高度 230px → 260px，标题放大到 1.32em，
移动端封面 190px。

### 踩过的坑

`.recent-post-item` **不是** `#recent-posts` 的直接子元素，中间还隔了一层
`.recent-post-items`，所以必须用后代选择器：

```css
/* ❌ 匹配不到 */
#recent-posts > .recent-post-item { }
/* ✅ 正确 */
#recent-posts .recent-post-item { }
```

## 三、文章封面

每篇文章的 front-matter 里指定：

```yaml
cover: /img/cover-life.svg
```

现有封面：

| 文件 | 用途 |
| --- | --- |
| `cover-life.svg` | 暖紫，柔和光斑 → 生活类 |
| `cover-tech.svg` | 冷紫，几何网格 → 技术类 |
| `default_cover.svg` | 没写 cover 时的默认封面 |

都是 SVG，任意缩放不糊，单张只有 1.4 KB。

## 四、测试

```bash
npm install --no-save jsdom   # 首次
node tests/test_css.js
```

会检查：
1. 自定义 CSS 里**每条选择器都能匹配到元素**（防止选择器写错导致静默失效）
2. 加载顺序正确（自定义在主题之后）
3. 关键变量的覆盖链路正确（主题旧值存在 + 自定义新值存在 + 后加载）
